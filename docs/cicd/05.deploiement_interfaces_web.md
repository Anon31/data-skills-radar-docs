# 🎨 5. Déploiement Continu des Interfaces Web (Frontend Angular & Portail Docsify)

> **Objectif de ce chapitre :** Documenter l'industrialisation Docker et CI/CD de mes deux interfaces web exposées en HTTPS : mon application **Frontend Angular 22 (`data-skills-radar-app`)** exploitant le pattern **URL Relative + Reverse Proxy (Zéro-CORS)** via un `Dockerfile` Multi-Stage à 4 étapes, et mon portail de documentation **Docsify (`data-skills-radar-docs`)** servi par une image Nginx Alpine ultra-légère (Zéro Build Node.js).

---

## 🖥️ 4.1. Conteneurisation et CI/CD du Frontend Angular (`data-skills-radar-app`)

> **Contexte :** Mon API Backend (NestJS) étant opérationnelle en Staging (`port 3001`) et en Production (`port 3000`), j'ai industrialisé le déploiement de mon application Frontend Angular pour la rendre accessible sur :
> *   **Staging (`develop`) :** `https://staging.dataskills.thomasnoel.dev` (Port VPS `4201`)
> *   **Production (`master`) :** `https://app.dataskills.thomasnoel.dev` (Port VPS `4200`)

### 1. Stratégie des Environnements Angular (« Cloud-Native »)

Plutôt que de multiplier les fichiers d'environnements Angular (`environment.staging.ts`, `environment.prod.ts`) avec des URLs codées en dur qui obligeraient à modifier la configuration du compilateur (`angular.json`) selon la branche Git, j'ai adopté le pattern **URL Relative + Reverse Proxy** :

#### A. Configuration Locale (`src/environments/environment.ts`)
Pour le développement sur mon PC (`ng serve`), Angular appelle directement mon API locale :
```typescript
export const environment = {
  production: false,
  API_URL: 'http://localhost:3000/api/v1',
  IMAGE_PATH: 'assets/img',
  ICONS_PATH: 'assets/icons',
  SVG_PATH: 'assets/svg',
  FONTS_PATH: 'assets/fonts',
};
```

#### B. Configuration Déployée (`src/environments/environment.prod.ts`)
Pour **tous les environnements déployés sur le serveur (Staging ET Production)**, j'utilise une **URL relative `/api/v1`** :
```typescript
export const environment = {
  production: true,
  API_URL: '/api/v1',
  IMAGE_PATH: 'assets/img',
  ICONS_PATH: 'assets/icons',
  SVG_PATH: 'assets/svg',
  FONTS_PATH: 'assets/fonts',
};
```

> [!TIP]
> **Pourquoi cette approche Cloud-Native est-elle supérieure ?**
> 1. **Zéro erreur CORS :** Le navigateur client voit que l'API et le Frontend résident sur exactement la même origine (`app.dataskills...` ou `staging.dataskills...`). Il n'envoie aucune requête *Preflight `OPTIONS`* bloquante.
> 2. **Routage dynamique par Nginx Hôte :** C'est le serveur Nginx du VPS qui inspecte l'URL entrante. Si la requête arrive sur `staging.dataskills.../api/v1`, il la route en interne vers le conteneur API Staging (`127.0.0.1:3001`). Si elle arrive sur `app.dataskills.../api/v1`, il la route vers le conteneur API Prod (`127.0.0.1:3000`). Une seule image Docker Angular est ainsi 100 % agnostique de l'environnement !

### 2. Le `Dockerfile` Multi-Stage Auto-Porteur (4 Étapes) & `.dockerignore`

Un conteneur Frontend en production ne doit jamais exécuter `ng serve` ni embarquer le dossier `node_modules` (> 500 Mo). J'ai conçu une architecture **Multi-Stage à 4 étapes** générant une image finale `nginx:stable-alpine` ultra-légère (~20 Mo).

#### A. Fichier `.dockerignore` (Optimisation du Build Context)
Pour éviter que Docker ne copie les 336 Mo du dossier `node_modules` généré par l'étape de CI sur le runner GitHub vers le démon Docker (`transferring context: 336.28MB`), j'ai placé ce `.dockerignore` à la racine de `data-skills-radar-app` :

```dockerignore
node_modules
dist
.angular
.git
.github
.idea
.vscode
```

#### B. Fichier `Dockerfile` (`data-skills-radar-app`)
> [!NOTE]
> **Astuce DevOps :** Plutôt que de maintenir un fichier `nginx.conf` externe séparé, j'injecte directement la règle de routage SPA (`try_files $uri $uri/ /index.html;`) et la compression Gzip via une commande `RUN echo` lors de la construction de l'étape 4.

```dockerfile
# --- ÉTAPE 1 : BASE COMMUNE (Installation des dépendances) ---
FROM node:24-alpine AS base
WORKDIR /usr/src/app
COPY package*.json ./
RUN npm ci
COPY . .

# --- ÉTAPE 2 : DÉVELOPPEMENT (Hot-Reload local optionnel) ---
FROM base AS development
RUN npm install -g @angular/cli
EXPOSE 4200
CMD ["npm", "start", "--", "--host", "0.0.0.0", "--poll", "2000"]

# --- ÉTAPE 3 : BUILD DE PRODUCTION ---
FROM base AS build
RUN npm run build -- --configuration=production

# --- ÉTAPE 4 : PRODUCTION (Image finale déployée sur le VPS) ---
FROM nginx:stable-alpine AS production

# Nettoyage de la page par défaut de Nginx et copie du build Angular
RUN rm -rf /usr/share/nginx/html/*
COPY --from=build /usr/src/app/dist/*/browser /usr/share/nginx/html

# Configuration Nginx injectée à la volée pour supporter le routage Angular (SPA)
RUN echo 'server { \
    listen 80; \
    gzip on; \
    gzip_types text/plain text/css application/json application/javascript text/xml application/xml application/xml+rss text/javascript; \
    location / { \
        root /usr/share/nginx/html; \
        index index.html index.htm; \
        try_files $uri $uri/ /index.html; \
    } \
}' > /etc/nginx/conf.d/default.conf

EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```

### 4. Pipeline CI/CD Frontend (`.github/workflows/deploy.yml`)

```yaml
name: CI/CD Pipeline - Data Skills Radar App (Frontend)

on:
  push:
    branches: [ "master", "develop" ]
  pull_request:
    branches: [ "master", "develop" ]

jobs:
  build-and-push:
    runs-on: ubuntu-24.04
    permissions:
      contents: read
      packages: write
    steps:
      - name: Checkout repository
        uses: actions/checkout@v6

      - name: Set environment variables
        run: |
          echo "IMAGE_NAME=$(echo ${{ github.repository }} | tr '[:upper:]' '[:lower:]')" >> $GITHUB_ENV
          if [[ "${{ github.ref_name }}" == "master" ]]; then
            echo "DOCKER_TAG=production" >> $GITHUB_ENV
          else
            echo "DOCKER_TAG=staging" >> $GITHUB_ENV
          fi

      - name: Setup Node.js
        uses: actions/setup-node@v6
        with:
          node-version: '24'
          cache: 'npm'

      - name: Install, Lint and Build Angular
        run: |
          npm ci
          npm run lint --if-present
          npm run build -- --configuration=production

      - name: Log in to GHCR
        if: github.event_name == 'push'
        uses: docker/login-action@v4
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}

      - name: Build and push Frontend image
        if: github.event_name == 'push'
        uses: docker/build-push-action@v7
        with:
          context: .
          file: ./Dockerfile
          target: production
          push: true
          tags: ghcr.io/${{ env.IMAGE_NAME }}:${{ env.DOCKER_TAG }}

  deploy:
    if: github.event_name == 'push'
    needs: build-and-push
    runs-on: ubuntu-24.04
    steps:
      - name: Set environment variables (CD)
        run: |
          echo "IMAGE_NAME=$(echo ${{ github.repository }} | tr '[:upper:]' '[:lower:]')" >> $GITHUB_ENV
          if [[ "${{ github.ref_name }}" == "master" ]]; then
            echo "DOCKER_TAG=production" >> $GITHUB_ENV
            echo "COMPOSE_FILE=docker-compose.prod.yml" >> $GITHUB_ENV
          else
            echo "DOCKER_TAG=staging" >> $GITHUB_ENV
            echo "COMPOSE_FILE=docker-compose.staging.yml" >> $GITHUB_ENV
          fi

      - name: Deploy to VPS via SSH
        uses: appleboy/ssh-action@v1.0.3
        with:
          host: ${{ secrets.VPS_HOST }}
          username: ${{ secrets.VPS_USERNAME }}
          key: ${{ secrets.VPS_SSH_KEY }}
          envs: IMAGE_NAME,DOCKER_TAG,COMPOSE_FILE
          script: |
            cd ~/data-skills-radar-app
            echo "${{ secrets.GITHUB_TOKEN }}" | sudo docker login ghcr.io -u ${{ github.actor }} --password-stdin
            sudo IMAGE_NAME=${IMAGE_NAME} docker compose -f ${COMPOSE_FILE} pull
            sudo IMAGE_NAME=${IMAGE_NAME} docker compose -f ${COMPOSE_FILE} up -d
```

### 5. Exposition Nginx Hôte (`/etc/nginx/sites-available/dsr-app`) & SSL

C'est dans ce fichier Nginx sur le VPS que s'opère le routage hybride de mon URL relative `API_URL: '/api/v1'` :
*   Tout le trafic commençant par **`/api/`** est intercepté et redirigé vers le conteneur **NestJS** correspondant (`3000` en Prod, `3001` en Staging).
*   Tout le reste du trafic (**`/`**) est envoyé vers le conteneur **Angular** correspondant (`4200` en Prod, `4201` en Staging).

```nginx
# 🚀 FRONTEND PRODUCTION (app.dataskills.thomasnoel.dev)
server {
    listen 80;
    server_name app.dataskills.thomasnoel.dev;

    # 1. Routage des appels API (/api/v1/...) vers le Backend de PROD (Port 3000)
    location /api/ {
        proxy_pass http://127.0.0.1:3000/api/;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # 2. Routage de l'interface web vers le conteneur Angular de PROD (Port 4200)
    location / {
        proxy_pass http://127.0.0.1:4200;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_cache_bypass $http_upgrade;
    }
}

# 🧪 FRONTEND STAGING (staging.dataskills.thomasnoel.dev)
server {
    listen 80;
    server_name staging.dataskills.thomasnoel.dev;

    # 1. Routage des appels API (/api/v1/...) vers le Backend de STAGING (Port 3001)
    location /api/ {
        proxy_pass http://127.0.0.1:3001/api/;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    # 2. Routage de l'interface web vers le conteneur Angular de STAGING (Port 4201)
    location / {
        proxy_pass http://127.0.0.1:4201;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_cache_bypass $http_upgrade;
    }
}
```

**Activation et génération des certificats HTTPS :**
```bash
sudo ln -s /etc/nginx/sites-available/dsr-app /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
sudo certbot --nginx -d app.dataskills.thomasnoel.dev -d staging.dataskills.thomasnoel.dev
```

## 📚 4.2. Conteneurisation et CI/CD du Portail Docsify (`data-skills-radar-docs`)

> **Contexte :** Pour finaliser l'exposition web du projet sur mon propre domaine avant d'attaquer le Data Lakehouse, j'ai déployé mon portail de documentation technique **Docsify (`data-skills-radar-docs`)** sur :
> *   **Production (`master`) :** `https://docs.dataskills.thomasnoel.dev` (Port VPS **`4300`**)

### 1. Architecture : Une Image Nginx Ultra-Légère (Zéro Build Node.js)

Contrairement à Angular qui nécessite une étape de compilation TypeScript/esbuild, **Docsify** interprète les fichiers `.md` directement à la volée dans le navigateur de l'utilisateur :
*   **Zéro dépendance Node.js en production :** Aucun `Dockerfile` Multi-Stage ni `npm install` requis.
*   **Performance maximale :** Un simple conteneur `nginx:stable-alpine` sert les fichiers statiques (`index.html`, `_sidebar.md`, `README.md`, `docs/`, `assets/img/`) avec la compression Gzip activée sur le type MIME `text/markdown`.
*   **Port dédié (`4300`) :** J'utilise `127.0.0.1:4300` sur le VPS (dans la continuité de `4200/4201`), laissant le port `8080` libre pour les interfaces Big Data.

---

### 2. Création du `.dockerignore` et du `Dockerfile` (`data-skills-radar-docs`)

#### A. Fichier `.dockerignore`
Évite de copier l'historique Git, les workflows CI/CD ou mes dossiers locaux de cours et notes privées (`assets/notes/`, `assets/reports/`) à l'intérieur de l'image Docker publique :

```dockerignore

.idea
.vscode

docker-compose*.yml
node_modules

assets/reports/
```

#### B. Fichier `Dockerfile`
> [!WARNING]
> **Point d'attention critique Nginx (`=404` vs `/index.html`) :**  
> Contrairement à une SPA Angular qui utilise le routage HTML5 (`PathLocationStrategy`), Docsify utilise un routage par hash (`/#/docs/...`) et cherche dynamiquement en AJAX si un fichier `_sidebar.md` spécifique existe dans chaque sous-dossier visité. Il est **crucial d'utiliser `try_files $uri $uri/ =404;`** : si l'on redirigeait vers `/index.html`, Nginx renverrait le code HTML de la page d'accueil au lieu d'une erreur `404` lorsqu'un sous-dossier n'a pas son propre `_sidebar.md`, ce qui remplacerait la barre latérale de gauche par la page d'accueil !

```dockerfile
FROM nginx:stable-alpine

# Nettoyage de la page par défaut de Nginx
RUN rm -rf /usr/share/nginx/html/*

# Copie de la documentation Docsify (index.html, _sidebar.md, README.md, docs/, assets/img/...)
COPY . /usr/share/nginx/html

# Configuration Nginx optimisée pour Docsify (Gzip sur Markdown + vraie 404 pour le fallback _sidebar.md)
RUN echo 'server { \
    listen 80; \
    gzip on; \
    gzip_types text/plain text/css text/markdown application/json application/javascript text/xml application/xml text/javascript image/svg+xml; \
    location / { \
        root /usr/share/nginx/html; \
        index index.html; \
        try_files $uri $uri/ =404; \
    } \
}' > /etc/nginx/conf.d/default.conf

EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```
