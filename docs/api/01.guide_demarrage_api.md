# 📘 Mon Guide de Démarrage et Implémentation - API Backend

Ce document est mon carnet de bord technique pour la construction de l'API REST `data-skills-radar-api` (NestJS). J'y documente pas-à-pas mes choix d'architecture, l'installation de mes dépendances, ma configuration et l'écriture de mon code.

*(Note : Ce fichier retrace mon cheminement pour le projet fil rouge et s'enrichit itérativement).*

## Chapitre 1 : Installation dynamique de mes dépendances

Plutôt que de faire un simple copier-coller d'un ancien `package.json` et de risquer d'importer de la dette technique, j'ai pris la décision d'architecte d'installer mes paquets dynamiquement via le terminal. Cela me garantit de récupérer les dernières versions stables et compatibles avec Node 24.

Mon objectif est de doter mon application NestJS des outils strictement nécessaires pour répondre à mon Architecture Hexagonale :

### 1.1. Utilitaires de base et Validation

Pour gérer mes variables d'environnement de manière sécurisée et valider strictement les données entrantes (DTOs) depuis mon frontend :

```bash
npm install @nestjs/config class-validator class-transformer
```

### 1.2. Authentification, Sécurité et Secrets (DevSecOps)

Pour sécuriser mon API, j'implémente la stratégie JWT (JSON Web Token) et le hachage des mots de passe.
*Note d'architecture : J'ai opté pour `bcryptjs` (pur JS) plutôt que `bcrypt` (C++) pour garantir une compatibilité totale entre mon environnement de développement Windows, mon WSL et mes futurs conteneurs Linux, évitant ainsi les problèmes de compilation `node-gyp`.*

Conformément à mon anticipation des ressources de mon VPS (12 à 24 Go de RAM), j'intègre dès maintenant `node-vault` pour préparer mon architecture à l'utilisation d'un serveur HashiCorp Vault pour la gestion de mes secrets en production.

```bash
npm install @nestjs/passport @nestjs/jwt passport passport-jwt passport-local bcryptjs node-vault
npm install -D @types/passport-jwt @types/passport-local @types/bcryptjs @types/node-vault
```

### 1.3. Base de données relationnelle (Le monde OLTP)

Pour gérer le cycle de vie de mes utilisateurs (login, sessions) de manière purement transactionnelle (séparé de mon stockage Big Data), j'utilise PostgreSQL couplé à l'ORM Prisma.

```bash
npm install @prisma/client pg
npm install -D prisma @types/pg
```

### 1.4. Moteur Analytique et Big Data (Le monde OLAP)

C'est la clé de voûte de mon architecture analytique. J'installe le connecteur natif pour permettre à mon API de faire du requêtage "Zero-ETL" directement sur mes fichiers Apache Parquet, sans surcharger la mémoire de mon serveur.

```bash
npm install duckdb
```

## Chapitre 2 : Configuration de l'Infrastructure Locale (Docker Compose)

Pour garantir une iso-parité de développement avec la production, je refuse d'installer des services lourds directement sur mon système hôte. Tout mon socle de données est conteneurisé.

J'ai créé un fichier `docker-compose.yml` à la racine de mon projet API :

```yaml
version: '3.8'

services:
  db:
    image: postgres:15-alpine
    container_name: dsr-postgres
    restart: always
    environment:
      POSTGRES_USER: dsr_admin
      POSTGRES_PASSWORD: dsr_password
      POSTGRES_DB: data_skills_radar_db
    ports:
      - "5432:5432"
    volumes:
      - dsr-postgres-data:/var/lib/postgresql/data

  pgadmin:
    image: dpage/pgadmin4
    container_name: dsr-pgadmin
    restart: always
    environment:
      PGADMIN_DEFAULT_EMAIL: admin@dataskillsradar.com
      PGADMIN_DEFAULT_PASSWORD: admin
    ports:
      - "5050:80"
    depends_on:
      - db

  vault:
    image: hashicorp/vault:latest
    container_name: dsr-vault
    restart: always
    ports:
      - "8200:8200"
    environment:
      VAULT_DEV_ROOT_TOKEN_ID: "root"
      VAULT_DEV_LISTEN_ADDRESS: "0.0.0.0:8200"
    cap_add:
      - IPC_LOCK

volumes:
  dsr-postgres-data:
```

**Lancement de l'infrastructure :**
```bash
docker compose up -d
```
