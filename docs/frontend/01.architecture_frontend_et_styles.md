# 🏗️ Architecture Frontend & Guide des Styles

Ce document définit les fondations techniques de l'interface **Data Skills Radar** (`data-skills-radar-app`), propulsée par **Angular (v22+)** en mode *Single Page Application* (SPA) et couplée à mon API Backend **NestJS**. Il intègre également la charte graphique "Web 3.0 / Deeptech" de l'application.

---

## 🚀 1. Architecture Client-Serveur & Consommation Sécurisée

Contrairement à une approche autonome exposant directement les données du stockage, mon application Angular s'inscrit dans une architecture **Full-Stack sécurisée** :

* **Séparation stricte OLTP / OLAP via l'API NestJS :** L'application Angular communique exclusivement en HTTP/REST (sécurisé par tokens **JWT** et gardes **RBAC**) avec mon API Backend `data-skills-radar-api`. Cela évite d'exposer des clés ou des accès directs au stockage côté navigateur.
* **Le Moteur Analytique (DuckDB côté Backend) :** Lorsqu'un utilisateur filtre la carte ou les indicateurs sur le dashboard Angular, l'API NestJS interroge à la volée la couche **Gold** de mon Data Lakehouse (fichiers **Apache Parquet** sur MinIO S3) via le driver natif **DuckDB Node.js**. Grâce au *Column Pruning* (lecture sélective des colonnes), les agrégats sont calculés en quelques millisecondes sans saturer la mémoire de PostgreSQL.
* **Réactivité Frontend (Angular Signals) :** Côté navigateur, j'exploite la réactivité fine des **Angular Signals** pour mettre à jour instantanément les composants graphiques et la cartographie dès la réception des payloads JSON de l'API, garantissant une fluidité maximale sur les filtres croisés.

## 🎨 2. Guide des Styles & Identité Visuelle (Web 3.0 / Deeptech)

L'interface repose sur une identité visuelle orientée Cyber/Tech avec des contrastes élevés, évoquant l'univers de l'IA et de la donnée :
* **Fond principal :** Très sombre (Gris "Slate" profond `slate-900` / `#0f172a`).
* **Accents lumineux :** 🔵 Bleu Électrique (Primaire : `#3b82f6` à `#2563eb`) et 🟣 Violet Néon (Secondaire : `#8b5cf6`).
* **Typographie :** *Space Grotesk* (Google Fonts), apportant un design startup futuriste.
* **Effets Visuels :** Ombres portées colorées et diffuses (`box-shadow` intenses) pour créer des effets de lueur (*Glow*).

### 🥇 Priorité 1 : Classes Utilitaires (Tailwind CSS v4)
**90 %** du design structurel est réalisé via des classes utilitaires (Flexbox, Grid, Marges, Paddings, Typographie).

### 🥈 Priorité 2 : UI Kit & Composants Natifs (PrimeNG 22)
Pour les éléments interactifs complexes (Formulaires, IftaLabels, Tableaux analytiques, Toasters, Modales), j'utilise exclusivement les composants **PrimeNG**.
* **Intégration parfaite :** La configuration de `app.config.ts` inclut un `cssLayer` (`order: 'theme, base, primeng'`) couplé au plugin `@import "tailwindcss-primeui";` pour garantir que Tailwind n'écrase jamais les styles natifs des composants PrimeNG.

### 🥉 Priorité 3 : Thème Centralisé & Design System (`dsr-theme.ts`)
Le CSS brut ou la création manuelle de variables CSS non structurées sont proscrits. L'ensemble de la charte graphique est piloté via la fonction `definePreset()` dans le fichier `dsr-theme.ts`.

## 🌍 3. Environnement et Rendu (SPA vs SSR)

* **Server-Side Rendering (SSR) :** Désactivé (`false`).
* **Ma justification d'architecte :**
    1. **Outil métier authentifié & sécurisé :** *Data Skills Radar* est un Système d'Information Décisionnel (SID) protégé par authentification JWT et RBAC. Le référencement par les moteurs de recherche (SEO) n'est pas requis.
    2. **Compatibilité Dataviz & Cartographie :** L'exécution exclusivement côté client (SPA) évite tout conflit de rendu serveur avec les librairies graphiques et cartographiques (Leaflet) manipulant directement les API du navigateur (`window`, `DOM`).

## 📂 4. Structure des Dossiers de l'Application Angular (`data-skills-radar-app`)

L'architecture du projet frontend repose sur une organisation modulaire stricte, séparant la logique transversale des fonctionnalités métiers :

```text
src/
└── app/
    ├── core/                 # Éléments globaux et transversaux
    │   ├── guards/           # Sécurisation des routes (JWT / RBAC)
    │   ├── pages/            # Pages système (Erreurs, NotFound)
    │   ├── services/         # Services HTTP globaux & Session
    │   └── utilities/        # Fonctions utilitaires partagées
    ├── features/             # Modules fonctionnels par domaine
    │   ├── auth/             # Authentification (Login, Register, Models)
    │   ├── home/             # Page d'accueil & Dashboard analytique principal
    │   └── users/            # Gestion des utilisateurs et profils
    ├── layout/               # Structure globale de l'interface
    │   ├── components/       # Éléments de structure (header, footer, sidebar)
    │   └── main-layout/      # Conteneur principal & routes associées
    ├── shared/               # Composants UI réutilisables & modèles communs
    ├── styles/               # Feuilles de style modulaires (_base, _button, _radar, etc.)
    │   └── theme/            # Définition du Design System (dsr-theme.ts)
    ├── app.config.ts         # Configuration globale de l'application (Providers, PrimeNG)
    ├── app.routes.ts         # Routeur principal de l'application SPA
    └── app.component.ts      # Composant racine
