# 🏗️ Architecture Frontend & Guide des Styles

Ce document définit les fondations techniques de l'interface **Data Skills Radar** (`data-skills-radar-app`), propulsée par **Angular (v22+)** en mode *Single Page Application* (SPA) et couplée à mon API Backend **NestJS**.

---

## 🚀 1. Architecture Client-Serveur & Consommation Zero-ETL

Contrairement à une approche où le navigateur interrogerait directement le stockage S3 (ce qui exposerait dangereusement les clés d'accès au Data Lakehouse côté client), mon application Angular s'inscrit dans une architecture **Full-Stack sécurisée** :

* **Séparation stricte OLTP / OLAP via l'API NestJS :** L'application Angular communique exclusivement en HTTP/REST (sécurisé par tokens **JWT** et gardes **RBAC**) avec mon API Backend `data-skills-radar-api`.
* **Le Moteur Analytique (DuckDB côté Backend) :** Lorsqu'un utilisateur filtre la carte ou les indicateurs sur le dashboard Angular, l'API NestJS interroge à la volée la couche **Gold** de mon Data Lakehouse (fichiers **Apache Parquet** sur MinIO S3) via le driver natif **DuckDB Node.js**. Grâce au *Column Pruning* (lecture sélective des colonnes), les agrégats sont calculés en quelques millisecondes sans jamais saturer la mémoire de PostgreSQL.
* **Réactivité Frontend (Angular Signals) :** Côté navigateur, j'exploite la réactivité fine des **Angular Signals** pour mettre à jour instantanément les composants graphiques et la cartographie dès la réception des payloads JSON de l'API, garantissant une fluidité maximale sur les filtres croisés.

## 🎨 2. Guide des Styles & Architecture UI

Mon projet adopte une architecture CSS hybride ultra-moderne reposant sur la synergie entre **Tailwind CSS v4** et **PrimeNG 22 (Aura Theme)**.

### 🥇 Priorité 1 : Classes Utilitaires (Tailwind CSS v4)
**90 %** du design structurel est réalisé via des classes utilitaires.
* **Pourquoi ce choix ?** Gestion native du responsive, standardisation des espacements, et compilation instantanée sans fichier de configuration complexe.
* **Usage :** Flexbox, Grid, Marges, Paddings, Typographie globale.

### 🥈 Priorité 2 : UI Kit & Composants Natifs (PrimeNG 22)
Pour les éléments interactifs complexes (Formulaires, IftaLabels, Tableaux analytiques, Toasters, Modales), j'utilise exclusivement les composants **PrimeNG**.
* **Intégration parfaite :** La configuration de `app.config.ts` inclut un `cssLayer` (`order: 'theme, base, primeng'`) couplé au plugin `@import "tailwindcss-primeui";`. Cela garantit que Tailwind n'écrase jamais les arrondis ou les paddings natifs des composants PrimeNG.

### 🥉 Priorité 3 : Thème Centralisé (Design System natif)
Le CSS brut ou la création manuelle de variables CSS (ex: `_tokens.css`) sont proscrits. L'ensemble de ma charte graphique est piloté par le fichier TypeScript `dsr-theme.ts` via la fonction `definePreset()`.
* **Mode Clair (Light) :** Couleurs de fond basées sur `{slate}` et couleur primaire `{teal}` (Cyan).
* **Mode Sombre (Dark) :** Couleurs de fond basées sur `{slate}` (bleu nuit) et couleur primaire `{amber}` (Orange).
* **Usage :** Tailwind lit automatiquement ce thème. Pour colorer un élément, j'utilise directement les utilitaires générés : `text-primary-500`, `bg-surface-50`, `border-surface-200`. La bascule clair/sombre se fait via la classe HTML `.dark` gérée par mon `SessionService` (sauvegardée en `LocalStorage`).

## 🌍 3. Environnement et Rendu (SPA vs SSR)

* **Server-Side Rendering (SSR) :** Désactivé (`false`).
* **Ma justification d'architecte :**
    1. **Outil métier authentifié :** *Data Skills Radar* est un Système d'Information Décisionnel (SID) protégé par authentification JWT et contrôle d'accès par rôles (RBAC). Le référencement par les moteurs de recherche publics (SEO) n'est donc pas un prérequis.
    2. **Compatibilité Dataviz & Cartographie :** L'exécution exclusivement côté client (SPA) évite tout conflit de rendu serveur Node.js avec les librairies de visualisation de données et de cartographie interactive (qui manipulent directement les API du navigateur comme `window` et le `DOM`).
